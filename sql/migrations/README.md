# 数据库结构变更规范

## 角色分工

- **`sql/init.sql`**：**初始化基线**。仅用于全新环境一键建库建表，**只增不改**，始终反映最新完整结构。
- **`sql/migrations/`**：**版本化增量变更**。已上线环境升级时，按版本号从小到大依次执行。

## 规则

1. **表结构有变更时**（新增/删除/修改字段、索引、约束，或新增/删除表），必须同时做两件事：
   - 在 `sql/migrations/` 新增一个版本脚本（只追加，**禁止修改已发布的历史脚本**）；
   - 同步更新 `sql/init.sql` 基线，保证全新环境初始化后结构与"基线 + 全部迁移"一致。
2. **版本命名**：`V{三位数字}__{描述}.sql`，版本号全局递增，如：
   - `V001__add_messages_sources_index.sql`
   - `V002__messages_add_correct_flag.sql`
3. **幂等**：迁移脚本尽量使用 `IF NOT EXISTS` / `IF EXISTS` 等幂等写法，允许重复执行。
4. **执行顺序**：升级时从 `V001` 开始按序执行到最新版本（未应用过的才执行）。
5. **不允许**：修改历史迁移文件、回滚已发布版本（如需回滚，另写一个反向迁移）。

## 迁移模板

```sql
-- ============================================================================
-- V00X__<简短描述>
-- 说明：<本次变更的背景与内容>
-- 应用范围：已上线环境增量执行（顺序执行：V001 -> V002 -> ...）
-- ============================================================================

USE manual_rag;

-- 示例：新增字段
ALTER TABLE messages
  ADD COLUMN correct_flag TINYINT(1) NOT NULL DEFAULT 0 COMMENT '回答是否正确标记（预留）' AFTER sources;

-- 示例：新增索引
ALTER TABLE feedbacks
  ADD INDEX idx_score (score) COMMENT '按分值统计的索引';
```

## 建议

- 任何表结构变更都应同步更新后端 ORM 模型（`backend/app/db/models.py`），保证 `create_all` 与 SQL 一致。
- 字段命名、注释请与既有风格保持一致（全小写下划线、UTF-8 中文注释、注明用途）。
