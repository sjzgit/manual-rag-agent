# 文档切片说明

> **最后更新**: 2026-08-04 | **切片版本**: v1.1

---

## 一、概述

本目录存放系统操作手册知识库的文档切片结果（`chunks.json`），用于 RAG（检索增强生成）场景下的向量化检索。切片将原始 MD 手册文档按功能模块拆分为独立的检索单元，每个单元包含完整的操作步骤文本及关联的截图引用。

**知识库源文档**: `处理后的md手册文档/` — 从 `.docx` 操作手册转换的结构化 Markdown 文档。

---

## 二、切片策略

### 2.1 核心原则

| 原则 | 说明 |
|------|------|
| **功能边界优先** | 以 H3 标题（`###`）对应的功能模块为最小切片单元 |
| **上下文完整** | 每个切片包含从根模块到当前模块的完整面包屑路径 |
| **图片原位保留** | 图片 `![](path)` 引用保留在切片文本中，不单独向量化 |
| **小模块合并** | 文本量不足 150 字符的相邻功能模块自动合并，避免碎片化 |

### 2.2 切片规则

```
文档标题 (#)
├── H2 (##)      一级模块 — 不单独切片，作为上下文路径
│   ├── H3 (###)   二级功能 — 切片单元
│   │   ├── H4 (####) 子功能 — 合并回父 H3，不独立切片
│   │   └── ...
│   ├── H3 合并  同级 H3 文本量 < 150 字符时自动合并
│   └── ...
└── ...
```

**规则详解**：

1. **H3 为切片主体** — Markdown 的三级标题（`###`）对应一个完整的功能操作，如「新增预约申请」「审核」「门禁绑定」等。
2. **H4 合并入 H3** — 四级标题是 H3 下的子页面（如 H3「首页」下的 H4「体检/体测」），内容少，合并到父 H3 中。
3. **兄弟合并** — 同一 H2 下，连续多个 H3 的纯文本（不含图片）少于 150 字符时，合并为一个切片，避免「操作系统要求」「浏览器要求」等零碎信息各自独立。
4. **面包屑注入** — 每个切片首行注入 `## H2 > H3` 格式的路径，Agent 可直接引用精确定位。

### 2.3 不向量化的内容

| 内容 | 处理方式 | 原因 |
|------|---------|------|
| 图片本身 | 仅保留 `![](path)` 文本引用 | 图片不参与语义检索，Agent 按需引用展示 |
| 免责声明/版权声明 | 已从源文档删除 | 与功能操作无关 |
| 文件修改记录 | 已从源文档删除 | 历史元数据，非操作知识 |
| 阅读对象 | 已从源文档删除 | 非操作内容 |

## 四、JSON 字段说明

每个切片为一个 JSON 对象，字段含义如下：

| 字段 | 类型 | 说明 | 示例 |
|------|------|------|------|
| `id` | string | 唯一标识，格式为 `{文档名}_{面包屑路径}`，可用作向量数据库的文档 ID | `"实验会议室预约操作手册_河南实验会议室_会议室预约审核"` |
| `doc` | string | 所属源文档名称 | `"实验会议室预约操作手册"` |
| `path` | string | 面包屑路径，` > ` 分隔，从一级模块到当前功能 | `"河南实验会议室 > 会议室预约审核"` |
| `level` | int | 路径层级深度（2 = H2 > H3，合并后可能更浅） | `2` |
| `chunk_index` | int | 该文档内的切片序号（从 0 开始） | `0` |
| `content` | string | **切片正文**，包含面包屑标题 + 操作步骤文本 + 图片引用，**这是实际送入向量化的内容** | 见下方示例 |
| `char_count` | int | 纯文本字符数（不含图片链接），可用于判断切片信息密度 | `525` |
| `has_images` | bool | 是否包含图片引用 | `true` |
| `image_count` | int | 包含的图片数量 | `18` |

### content 字段示例

```markdown

在审核列表中，点击状态为「审核中」的预约记录，可选择「通过」或「不通过」进行操作

完成审核操作后，点击「保存」即可完成审核
```

## 五、meta_data.json 索引文件

`meta_data.json` 是切片的关键词索引，用于快速匹配用户问题到相关切片。

### 5.1 字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string | 切片唯一标识，与 `chunks.json` 中的 `id` 完全一致 |
| `doc` | string | 所属源文档名称 |
| `path` | string | 面包屑路径 |
| `keywords` | string[] | **功能关键词列表**，涵盖该切片涉及的所有功能点、操作动作、角色、实体等 |

### 5.2 关键词设计原则

| 维度 | 示例 | 目的 |
|------|------|------|
| **功能模块** | 会议室预约、作品维护、过程管理 | 定位功能域 |
| **操作动作** | 新增、删除、审核、授权、撤回 | 匹配用户意图 |
| **角色身份** | 教职工、会议室管理员、他评组长 | 权限相关查询 |
| **关键实体** | 开门码、佐证材料、推荐度、设备SN | 精确概念匹配 |
| **操作对象** | 班牌端、移动端、Pc端、大屏 | 区分操作环境 |

### 5.3 使用示例

```python
import json

with open("meta_data.json", "r", encoding="utf-8") as f:
    meta = json.load(f)

# 场景1: 用户问"怎么新增会议室预约？"
query_kw = ["新增", "预约", "会议室"]
matches = []
for m in meta:
    score = sum(1 for kw in query_kw if any(kw in mk for mk in m["keywords"]))
    if score > 0:
        matches.append((score, m))

matches.sort(reverse=True)
top = matches[0][1]
# top["id"] → "实验会议室预约操作手册_河南实验会议室_..."
# 然后用 id 从 chunks.json 取完整内容

# 场景2: 判断用户问题是否完整
# 如果匹配到的切片 keywords 中存在用户未提及的功能点，
# 可追问用户是否也需要了解
```

## 六、使用方式

### 6.1 向量化

将每个切片的 `content` 字段送入 Embedding 模型：

```python
import json

with open("chunks.json", "r", encoding="utf-8") as f:
    chunks = json.load(f)

texts = [chunk["content"] for chunk in chunks]
# texts → Embedding Model → 向量数据库
```

### 6.2 检索后引用图片

Agent 检索到切片后，通过切片中保留的 `![](./media/xxx.png)` 引用，向用户展示对应的操作截图：

```python
# 检索命中后
matched = chunks[3]
# 回答中引用：
answer = f"{matched['content']}"
# 图片路径相对于 处理后的md手册文档/{doc}/media/
```

### 6.3 元数据过滤

可利用 `doc`、`path` 字段实现按文档或模块过滤：

```python
# 仅搜索「会议室」相关
filtered = [c for c in chunks if "会议室" in c["path"]]
```

## 八、调整切片策略

如需调整切片参数（最小字符数、合并策略等）：

1. 修改切片脚本中的 `MIN_CHARS` 等参数
2. 重新运行切片生成新的 `chunks.json` 和 `meta_data.json`
3. **必须同步更新本 README**：修改「二、切片策略」和「七、变更记录」
