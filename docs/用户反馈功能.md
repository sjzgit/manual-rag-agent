## 1. 背景与目标

C 端会话结果已有「点赞/踩」功能，反馈已写入 `feedbacks` 表（`message_id`/`score` 1|-1/`comment`/`created_at`），但后台管理端无可视化入口。本功能在管理端新增「用户反馈」页面，并提供**工单**能力把零散反馈归集为可跟踪、可处理的工单。

**已确认的产品决策**：
1. 关联方式：**反馈侧发起**（勾选多条反馈 → 新建工单并关联 / 加入已有工单）。
2. 状态流转：**自由切换**（不校验顺序）。
3. 工单额外字段：增加**优先级** `priority`（high/medium/low）。

## 2. 功能清单

| 模块 | 功能 | 说明 |
| --- | --- | --- |
| 反馈列表 | 查看反馈 | 分值（赞/踩）、评语、所属会话标题、被反馈消息内容、时间 |
| 会话详情复用 | 查看会话 | 点击反馈「查看会话」，复用会话管理详情组件 `SessionDetailDrawer` |
| 工单 | 新建/列表/详情 | 工单含标题、优先级、状态、处理时间、处理结果、关联反馈数 |
| 工单状态 | 四态自由切换 | pending 待处理 / processing 处理中 / resolved 已处理 / closed 已关闭 |
| 关联 | 多对多 | 反馈侧勾选 → 新建工单并关联 / 加入已有工单；工单详情可解除关联 |

## 3. 数据库设计

### 3.1 新增表 `tickets`（工单）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | INT AUTO_INCREMENT PK | 工单自增 ID |
| title | VARCHAR(256) NOT NULL | 工单标题 |
| status | VARCHAR(16) NOT NULL DEFAULT 'pending' | pending / processing / resolved / closed |
| priority | VARCHAR(16) NOT NULL DEFAULT 'medium' | high / medium / low |
| result | TEXT NULL | 处理结果（处理完成后填写） |
| processed_at | DATETIME NULL | 处理时间（进入 resolved/closed 时记录，回到 pending/processing 时清空） |
| created_at / updated_at | DATETIME | 创建/更新时间 |
| 索引 | idx_status(status) | 按状态筛选 |

### 3.2 新增关联表 `feedback_tickets`（多对多）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | INT AUTO_INCREMENT PK | 关联记录自增 ID |
| feedback_id | INT NOT NULL | 反馈 ID（逻辑外键 → feedbacks.id） |
| ticket_id | INT NOT NULL | 工单 ID（逻辑外键 → tickets.id） |
| created_at | DATETIME | 关联时间 |
| 约束 | UNIQUE(uk_feedback_ticket)(feedback_id, ticket_id) | 防重复关联 |
| 索引 | idx_ticket(ticket_id) | 按工单查反馈 |

> 唯一键左前缀已覆盖 feedback_id 查询，故不单建 idx_feedback。

### 3.3 三同步

- `sql/migrations/V004__add_tickets.sql`（增量）
- `sql/init.sql`（基线追加）
- `backend/app/db/models.py`（ORM：`Ticket` / `FeedbackTicket`，后者声明 `UniqueConstraint`）

约束遵循：零物理外键、逻辑外键 + 显式索引、全小写下划线、中文 COMMENT、utf8mb4。

## 4. 后端设计

分层：`api/admin_feedback.py`（薄路由）→ `services/feedback_service.py`（编排）→ `db/models.py`（持久化）。

### 4.1 Service（`feedback_service.py`）

`FeedbackService(db)`，风格与 `session_service.py` 一致（DB 不可用降级、try/except + logger.warning）。

| 方法 | 说明 |
| --- | --- |
| `list_feedbacks(offset, limit)` | `Feedback→Message→Session` **outerjoin**（兜底悬空 message_id），返回 `{feedbacks, total}` |
| `list_tickets(offset, limit)` | `select(Ticket, count(FeedbackTicket.id)).outerjoin(...).group_by(Ticket.id)` 聚合 `feedback_count` |
| `get_ticket(ticket_id)` | 返回 `{ticket, feedbacks}` |
| `create_ticket(title, priority, feedback_ids, status)` | 建单 + `flush()` 拿 id 后批量插关联 |
| `update_ticket(...)` | 部分更新；`processed_at` 随 status 推导 |
| `link_feedbacks(ticket_id, feedback_ids)` | 先查后插去重，返回新增条数 |
| `unlink_feedback(ticket_id, feedback_id)` | 删除单条关联 |

### 4.2 API（`admin_feedback.py`）

| # | Method + Path | 说明 |
| --- | --- | --- |
| 1 | `GET /admin/api/feedbacks?offset&limit` | 反馈列表 |
| 2 | `GET /admin/api/tickets?offset&limit` | 工单列表 |
| 3 | `POST /admin/api/tickets` | 新建工单（可带 feedback_ids 关联） |
| 4 | `GET /admin/api/tickets/{id}` | 工单详情（含关联反馈） |
| 5 | `PUT /admin/api/tickets/{id}` | 更新工单（状态/优先级/标题/结果） |
| 6 | `POST /admin/api/tickets/{id}/feedbacks` | 加入已有工单 |
| 7 | `DELETE /admin/api/tickets/{id}/feedbacks/{feedback_id}` | 解除关联 |

分页约定：`offset`(0) + `limit`(50)，返回 `{资源复数, total}`；时间 ISO 字符串。

### 4.3 注册

- `main.py` lifespan 实例化 `FeedbackService(db)` 挂 `app.state.feedback_service`。
- `create_app` 注册 `feedback_router` 与 `ticket_router`。

### 5.2 API（`api/admin.ts`）

### 5.3 路由与菜单

- `router/index.ts` 加 `/admin/feedback`。
- `AdminLayout.vue` 菜单加「用户反馈」（icon Inbox）。

### 5.4 抽组件 `SessionDetailDrawer.vue`

从 `SessionManage.vue` 抽出详情抽屉：props `modelValue` + `sessionId`，emit `update:modelValue`，内部 watch 加载 `getAdminSession` + `getSessionLogs`。`SessionManage` 与 `FeedbackManage` 共用。

### 5.5 页面 `FeedbackManage.vue`

`el-tabs` 两个 tab：
- **反馈列表**：`el-table` 多选列 + 分值 tag + comment + session_title + message_content + 时间 + 「查看会话」；顶部「新建工单并关联」「加入已有工单」。
- **工单列表**：标题 + 状态 tag + 优先级 tag + 关联反馈数 + 处理时间 + 「详情」；顶部「新建工单」。

**反馈侧发起交互**：勾选 N 条 → 新建工单弹窗（标题默认取首条 comment 截断 + 优先级 + 预览）或加入已有工单弹窗（选工单 + 预览）→ 提交后刷新并提示。

### 5.6 el-tag 颜色映射

| 字段 | 值 | type |
| --- | --- | --- |
| score 赞 / priority high / status resolved | — | success |
| score 踩 / priority high | — | danger |
| priority medium / status pending | — | warning |
| priority low / status closed | — | info |
| status processing | — | primary |

## 8. 风险与注意点

- 多对多去重：唯一键兜底 + 先查后插。
- DB 降级：service 返回 None/False，路由空列表/503/404。
- N+1：feedback_count 用 group_by 聚合。
- 三同步：V004 + init.sql + models.py 完全一致。
- 历史脏数据：列表 outerjoin，session 字段为 null 时前端 `?? '-'` 并禁用「查看会话」。
- 零物理外键：不引入 ForeignKey，本次不实现工单删除。
- 无鉴权：与 admin_session 等管理路由一致。
