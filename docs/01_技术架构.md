## 1. 产品概述

面向企业内部员工的操作手册智能问答系统。用户在网页端以对话形式提问，系统按 **"意图识别 → 反问澄清 → 向量检索（关联手册优先） → LLM 回答"** 流水线处理：

1. **意图识别（独立小模型，纯 Prompt 驱动）**：**结合会话历史**理解指代与承接（"那审批流程呢"→沿用历史模块），拆分多子问题、抽取"功能模块 / 用户角色 / 功能点"三要素，逐子问题判定为 **不相关（拒答）/ 精确（直接检索）/ 模糊（反问澄清）**。不依赖关键词索引、不做切片匹配，功能是否被知识库收录由后续向量检索决定。LLM 输出 JSON 后先经代码校验并尝试修复，失败用 Prompt 重试一次，仍失败判模糊并友好提示用户补充详细信息。
2. **反问澄清**：存在模糊意图时，后端下发 clarify 事件，前端展示询问对话框收集用户补充，合并后重新识别，直到全部精确（最大 3 轮防死循环）。
3. **会话记忆·关联手册优先检索（可选，`MEMORY_DIRECT_ANSWER` 开关）**：检索作答后把命中文档 id 合并进 `sessions.memory_docs`（仅存 doc_id、上限 3 个）；后续提问先在关联手册范围内混合检索（`doc in [...]` 过滤），命中分数 ≥ `memory_direct_score_threshold`（默认 0.6，rerank 分量纲）直接采用，不足自动转全库检索。回答始终只用最终命中的切片，任何阶段不注入手册全文。详见 `docs/会话记忆-关联手册优先检索.md`。
4. **混合检索**：逐子问题 BGE 稠密 + BM25 稀疏双路召回（top_k=20），加权 RRF 融合、阈值过滤、按父切片去重后可选 rerank（SiliconFlow，top_n=5），命中子切片回溯父切片（H3 完整功能模块），合并父内容与对话历史交给 LLM。检索作答后把命中文档 id 合并进会话记忆。
5. **LLM 回答**：DeepSeek 流式生成，回答必须基于提供的检索切片上下文，依据不足明确回复"手册中未找到"，末尾附"来源：文档名 > 路径"。

前端全程过程可视化（意图识别、检索命中、工具调用、思考过程），来源卡片展示切片原文及其中操作截图。

### 质量目标（第一版）

- 回答必须基于检索内容；检索不到则明确说"手册中未找到"
- 每次回答展示来源路径与切片原文（含图片）
- 意图识别、检索等过程对用户可见、可审计（全部落库）

## 2. 核心功能清单

| 模块 | 功能 | 说明 |
| --- | --- | --- |
| 意图识别 | 输入优化 | 去除问候语/重复/无意义信息；多问题拆分为子问题分别识别 |
| | 上下文结合 | 结合会话历史理解指代/承接，补全省略的模块要素；闲聊短句不误判为追问 |
| | 三要素抽取 | `{"module","role","description"}`，缺字段为空，可从历史补全 |
| | JSON 校验修复 | 代码校验 LLM 输出：剥 markdown 围栏、截取 JSON 主体、去尾逗号、逐字段容错（非法 intent_type 修正、missing_fields 过滤）；失败用 Prompt 重试一次，仍失败判 vague 友好提示 |
| | 三分类判定 | irrelevant（明显无关/敏感/非法，固定话术拒答）/ precise（能确定模块与功能点，角色非必填）/ vague（缺要素，输出 missing_fields + clarify_question） |
| | 降级策略 | 小模型未配置时：闲聊/无关领域词拒答、模糊指代澄清、历史模块正则补全（「xx操作手册/xx系统」）、其余判精确交由检索兜底 |
| 会话记忆 | 关联手册记忆 | 检索作答后把命中文档 id 合并进 `sessions.memory_docs`（仅存 id、去重、上限 3、不淘汰）；doc_name→doc_id 经 source_documents 反查 |
| | 关联手册优先检索 | 后续提问先在关联手册范围内混合检索（`doc in [...]`），每个子问题独立判定：命中分数 ≥ `memory_direct_score_threshold`（0.6）直接采用（step 标注「会话关联手册内」），不足自动转全库（step 提示转全库）；回答只用最终命中切片 |
| | 功能开关 | `MEMORY_DIRECT_ANSWER`（默认开）：读取记忆处生效，关闭时始终全库检索；关闭期间仍正常记录关联 |
| 反问澄清 | clarify 事件 | SSE 下发 `{question, missing_fields, intents}`，前端内嵌询问卡片 |
| | 轮次限制 | 默认 ≤3 轮，超限按最相关切片直接回答并提示 |
| 向量检索 | 稠密检索 | BGE `bge-base-zh-v1.5` 归一化向量，Milvus COSINE，子切片 top_k=8/子问题，可配阈值过滤 |
| | 父子回溯 | 命中子切片 → `child_id→parent_id` 回溯父切片 → 按父去重 → 按 doc+chunk_index 文档序排序；父展示分取子命中最高分 |
| | 原文映射 | 启动从 MySQL `chunks` 表加载父切片原文映射（DB 无数据时回退旧 chunks.json 单层兜底） |
| 过程可视化 | step 事件 | 意图识别结果、检索命中（含相似度）、工具调用、思考过程实时推送；步骤结果（intents/hits）随 `messages.steps.detail` 持久化，管理端可回看 |
| 来源图片 | 图片服务 | `/api/images/{doc}/{filename}` 优先取 `uploads/{doc}/media/`、回退 `处理后的md手册文档/{doc}/media/`，路径穿越校验；`./media/x.png` 改写为可访问 URL |
| 会话 | 多轮对话 | session 维度历史存 MySQL，每轮重建 Agent 记忆（服务无状态） |
| 反馈审计 | 赞/踩 + 评语 | 关联 message_id；意图日志、检索日志、审计日志全量落 MySQL |
| 后台管理端 | 知识库管理 | 上传 docx → mammoth 转 md（清洗封面/目录/免责声明等 + 图片提取上传）→ 代码切片（父子 v2.0）→ BGE 向量化入 `manual_rag_child_chunks` → `vector_state`/`vector_id` 回写；在线预览 word/md、切片列表 |
| | 提示词管理 | 硬编码 prompt 迁入 `prompt_templates` 表，`PromptService` 内存缓存读取，编辑即时生效，DB 不可用回退代码常量 |
| | 会话管理 | 会话列表/详情，展示消息、来源切片（含得分）、过程步骤明细、意图/检索日志 |

## 3. 技术栈

| 层级 | 选型 |
| --- | --- |
| Web API | FastAPI + Uvicorn（模块化单体，全异步） |
| Agent 编排 | AgentScope `>=2.0.5,<2.1`（ReActAgent + Toolkit + InMemoryMemory，不绑定其内置 RAG 存储） |
| 主 LLM | DeepSeek（`OpenAIChatModel` + `client_kwargs={"base_url": ...}`，OpenAI 兼容可切换） |
| 意图识别小模型 | 独立 OpenAI 兼容配置 `INTENT_LLM_BASE_URL / INTENT_LLM_API_KEY / INTENT_LLM_MODEL`（Key 待补充），低温度短输出 |
| 向量检索 | pymilvus + 现有 Milvus（FLAT/COSINE，dim=768），子切片 collection `manual_rag_child_chunks` |
| Embedding | sentence-transformers + `BAAI/bge-base-zh-v1.5`（lifespan 单例，`asyncio.to_thread` 包装） |
| 切片/索引 | 代码化父子切片（`app/knowledge/chunker.py`，纯代码非 LLM）；启动从 MySQL `chunks` 表加载父子映射，路径入 .env |
| docx 转换 | mammoth（docx→HTML）+ BeautifulSoup（清洗非操作内容）+ markdownify（HTML→md）；图片提取到上传目录 |
| 配置 | Pydantic / pydantic-settings（.env，密钥不落代码） |
| 持久化 | MySQL（SQLAlchemy 2.0 async + aiomysql） |
| 缓存限流 | Redis（第 5 步） |
| 前端 | Vue 3 + TypeScript + Element Plus + Pinia + Vue Router 4 + Vite 5 + Tailwind CSS 3.4.17 + lucide-vue-next |
| 日志 | structlog 结构化日志 + AgentScope Tracing 预留 |
| 测试 | pytest + httpx AsyncClient |
| 部署 | Docker Compose + Nginx（Milvus 走外部地址） |

### 对话流水线状态机

```
用户提问
  → 读取会话记忆 memory_docs（doc_id ≤3；MEMORY_DIRECT_ANSWER 开启时）→ 反查手册名列表
  → 意图识别（step: intent；LLM 输出 JSON → 代码校验/修复 → 失败重试一次 → 仍失败判 vague 友好提示）
  → 存在 irrelevant？→ 固定话术拒答（落库，结束）
  → 存在 vague？→ clarify 事件 → 前端询问框 → 用户补充 → 与原输入合并重新识别（≤3 轮）
  → 全部 precise → 逐子问题两段式检索（step: retrieve）：
      有关联手册 → 先范围内混合检索（doc in [...]，scope=memory）
        ├─ 命中分数 ≥ memory_direct_score_threshold → 直接采用
        └─ 不足 → step「关联手册命中不足，转全库检索」→ 全库重检（scope=global）
      无关联手册 → 直接全库检索
  → 命中低于阈值 → "手册中未找到"
  → 合并切片 + 历史 → AgentScope/DeepSeek 流式生成（step: thinking / token）
  → sources 事件（切片原文 markdown + 图片 URL）→ done（message_id）
  → 意图/检索/消息异步落 MySQL；检索作答后把命中文档 id 合并进 memory_docs（≤3）
```

## 6. 关键契约

### 6.1 意图识别输出（每子问题）

```json
{
  "intents": [
    {
      "input": "这个怎么审核？",
      "simple_input": "怎么审核",
      "module": "",
      "role": "",
      "description": "审核操作",
      "intent_type": "vague",
      "missing_fields": ["module"],
      "clarify_question": "请问您想审核哪个系统或功能模块中的内容？",
      "intent_reason": "当前输入未明确审核对象，历史对话也无法确定具体业务模块。"
    }
  ]
}
```

字段说明：`missing_fields` 仅在 vague 时列出真正缺失的要素（module/role/description，role 非必填）；`clarify_question` 仅 vague 时由 LLM 直接生成，澄清时优先使用、模板兜底，不再二次调用 LLM；已移除 `chunk_id_list`（不做切片匹配，收录与否由向量检索决定）与 `memory_answer_docs`（会话记忆 v2 不再由意图识别判断，改为检索阶段范围内优先，见 `docs/会话记忆-关联手册优先检索.md`）。

识别接口 `recognize(question, history=None)`：`history` 为会话历史消息（不含当前输入，全量注入不截断）。LLM 路径将历史作为多轮 user/assistant 消息注入 prompt；输出 JSON 先代码校验修复（剥 markdown 围栏 / 截取 JSON 主体 / 去尾逗号 / 逐字段容错），失败重试一次，仍失败判 vague 并输出友好补充提示。规则降级路径从历史文本用正则「xx操作手册 / xx系统」提取最近模块，用于承接性提问补全。`simple_input` 为结合历史补全后的完整问题（如 `"实验会议室预约：那审批流程呢？"`），用于向量检索。

### 6.2 SSE 事件协议

```
event: step    data: {"type":"intent|retrieve|thinking|tool_call","title":"...","detail":{...}}
event: clarify data: {"question":"...","missing_fields":["module"],"intents":[IntentResult]}
event: token   data: {"text":"..."}
event: sources data: {"sources":[{"doc","path","score","content","images":["/api/images/..."]}]}
event: done    data: {"message_id":"..."}
event: error   data: {"code":"...","message":"..."}
```

### 6.3 检索工具（AgentScope tool schema 来源）

```python
async def search_manual(query: str, doc: str | None = None, top_k: int = 8) -> list[SearchResult]:
    """从操作手册知识库检索与问题相关的切片。query 为用户问题，doc 可按手册名过滤，top_k 为返回条数。
    命中子切片后返回子级 path（定位精确）+ 父切片 content（内容完整）。"""
```

## 9. 关键决策（ADR）

- **ADR-001 采用 AgentScope 2.x**：管理 Agent、工具、会话与追踪，不绑定其内置 RAG 存储；锁定 `>=2.0.5,<2.1` 并写集成测试
- **ADR-002 保留自建 Milvus 检索层**：`manual_rag_chunks` 为唯一知识源，pymilvus 直接检索，保留 doc/path 元数据与来源引用，数据零迁移
- **ADR-003 意图识别独立小模型**：与主模型配置隔离，JSON 强约束输出 + 代码校验修复 + 一次重试 + vague 兜底；未配置时规则降级，保证链路可用
- **ADR-004 流水线状态机而非自由 Agent**：意图→澄清→检索→回答顺序显式可控、过程可观测；Agentic 模式（search_manual 工具化）作为第 5 步增强，配置开关切换
- **ADR-005 无状态服务 + 记忆重建**：每轮从 MySQL 重建 InMemoryMemory，支持水平扩展；澄清状态存会话 JSON 字段，断线可恢复
- **ADR-006 图片链路**：Milvus 存 clean 文本用于检索，展示原文取自 chunks.json 内存映射，`./media/` 改写为后端图片路由
- **ADR-007 意图识别结合会话上下文**：识别输入 = 当前问题 + 会话历史（**全量注入不截断**，2026-09-01 修复早期截断 BUG 后确认的行为）。LLM 路径把历史注入多轮 messages，由 Prompt 内上下文规则补全指代/承接；规则降级路径从历史文本正则提取最近模块（「xx操作手册/xx系统」核心名），用于承接性提问补全判 precise；闲聊/礼貌短句不结合历史，保持拒答
- **ADR-008 意图识别取消 meta_data 索引，改纯 Prompt 驱动（2026-08-17）**：依据 `chat/意图识别/改为prompt.md`。不再加载 meta_data.json 关键词索引、不做切片匹配——是否收录由向量检索决定，避免小模型"猜测知识库"造成的误判/漏判；意图识别 Prompt 直接生成 missing_fields 与 clarify_question，省去澄清问题的二次 LLM 调用；LLM 输出经"代码校验 → 修复 → Prompt 重试一次 → 仍失败判 vague 友好提示"保障可用性
- **ADR-009 父子切片 v2.0 + 后台管理端（2026-08-18）**：依据 `chat/后台管理端/后端管理基础功能.md` 与 `docs/文档切片策略.md` 第七节。切片改为代码化父子结构——父切片=H3 完整功能模块（存 MySQL chunks 表，不入向量库），子切片=H4/语义段（入新 collection `manual_rag_child_chunks`，向量状态与 vector_id 回写 chunks 表）；检索链路改为「子切片命中 → 回溯父切片 → 按父去重 → 文档序排序」，`retrieve_top_k` 2→8。管理端在现有项目内扩展（前端 vue-router `/admin` 路由 + 后端 `/admin/api/*`），覆盖知识库管理（docx 上传→mammoth 转 md→清洗→切片→向量化入库）、提示词模板管理（prompt_templates 表 + PromptService，DB 不可用回退代码常量）、会话管理（复用既有日志表展示检索切片/得分）
- **ADR-010 会话记忆·关联手册直接作答（2026-09-01，已被 ADR-011 取代）**：检索作答后把命中文档 doc_id 合并进 `sessions.memory_docs`（上限 3），意图识别注入关联手册全文并输出 `memory_answer_docs` 判断可直答，可直答则跳过检索、全文作上下文生成，依据不足输出 `[[NEED_RETRIEVAL]]` 回退检索。上线评估发现成本与质量问题（见 ADR-011），方案整体废弃。
- **ADR-011 会话记忆 v2·关联手册优先检索（2026-09-01）**：依据 `docs/会话记忆-关联手册优先检索.md`。废弃 v1 全文直答——意图小模型与生成主模型**两次注入手册全文**，token 与延迟反噬收益；「能否直答」塞进意图识别**职责错位**；整本手册注入后漏看/误答概率升高（「同一本手册」≠「问题在上次命中的段落」）。v2 保留 `sessions.memory_docs`（V008 列沿用，仅存 doc_id ≤3），记忆改为检索阶段的**优先范围**：每轮 doc_id → 手册名（≤3 行主键查询），逐子问题先在范围内混合检索（Milvus `doc in [...]` 过滤），命中分数 ≥ `memory_direct_score_threshold`（0.6，rerank 分量纲，高于基础阈值 0.4 防误锁旧手册）直接采用，不足自动全库（step 提示转全库，scope 字段落 outcome）；每个子问题独立判定，天然支持混合来源；回答只用最终命中切片，任何阶段不注入全文。意图识别回归三职责（无关判断/三要素/指代消解），历史注入维持全量。删除 v1 的 `memory_answer_system` 提示词、`[[NEED_RETRIEVAL]]` 标记、Redis `docmd:` 全文缓存（V010 迁移恢复 intent_system）。开关 `MEMORY_DIRECT_ANSWER` 改为记忆读取处生效（关闭即纯全库；记忆仍持续累积）。agentic 工具检索不接范围（Agent 自主检索）。

## 11. 风险与注意事项

- **不改动** `vector_store/` 现有脚本；`文档切片/chunks.json` / `处理后的md手册文档/` 只读使用（meta_data.json 已废弃，不再加载）；管理端上传/转换/图片写入走独立目录 `uploads/`，不触碰只读知识库
- **父子切片直接切换**：检索链路已切到 `manual_rag_child_chunks`，4 本手册须通过管理端重新上传入库后方可检索；`images.py` 保留 `media_root` 回退兼容切换窗口期
- mammoth 对复杂 Word 排版（文本框/艺术字/自定义标题样式）保真度有限；清洗规则按标题关键词+位置判断，转换结果保留 preview.html 供人工核对，支持「重新处理」
- 图片路由校验 doc/filename，防路径穿越；不相关/敏感问题固定话术拒答
- AgentScope 全异步：pymilvus / sentence-transformers / mammoth 同步调用一律 `asyncio.to_thread`
- SSE 前端用 fetch + ReadableStream（EventSource 不支持 POST/自定义头）；断连取消 LLM 流
- structlog 记录 session_id、各阶段耗时、命中数、token 用量；**不记录 API Key**
- 意图小模型 Key 待用户补充（.env 中 INTENT_LLM_*），补充前系统自动降级为规则匹配
- 管理端上传接口后台异步处理（转换/切片/向量化），前端轮询状态；BGE 编码复用 retriever 单例模型，不重复加载
- **会话记忆·关联手册优先检索**：范围内命中是常态、分数不足多走一次全库检索（含重排），漂移场景成本可控；`.env` 置 `MEMORY_DIRECT_ANSWER=false` 可整体关闭（始终全库）；`intent_system` 提示词在库中被恢复为三职责版本（V010），如管理端有自定义内容执行前需备份；范围采用阈值 `MEMORY_DIRECT_SCORE_THRESHOLD`（默认 0.6）可按 rerank 模型实测分布调整
