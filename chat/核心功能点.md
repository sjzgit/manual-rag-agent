## UI交互功能点：

1. 需要展示对话依据，把检索到的切片展示出来，并展示出切片原文中的图片。原始切片在`F:\工作备忘录\修炼\叶小钗\AI-10\操作手册RAG\文档切片\chunks.json`。
2. 智能体要可以向用户提问，后端返回用户确认的标识后，UI需要展示询问对话框，让用户补充回答后再继续对话
3. 智能体要将：意图识别、工具调用、向量检索、思考过程等详细过程展示给用户

## 智能体工作流：

### 意图识别

1. 意图识别需要单独配置小模型，提供OPENAI的API格式配置，我到时候补充，确保意图识别速度快
2. 一个完整的操作手册问题包含如下**必要元素**，如：实验室预约功能中管理员如何发起预约实验室
   1. 功能模块名称或系统名称：实验室预约功能
   2. 用户角色：管理员
   3. 功能点描述：如何发起预约实验室
3. 意图识别的核心算法：
   1. 先优化用户输入：
      1. 用户的输入可能包含多个功能操作问题，这时意图识别需要按照上述必要元素将用户输入拆分为多个字问题，分别进行意图识别
      2. 简化用户输入中的无关信息，比如：问候语、重复信息、无意义信息等
      3. 将用户输入的问题按如下格式拆分，如果缺少相关字段信息则为空：
```json
{
  "module": "功能模块名称或系统名称",
  "role": "用户角色",
  "description": "功能点描述"
}
```
   2. LLM根据用户问题在文档切片索引json文档(`F:\工作备忘录\修炼\叶小钗\AI-10\操作手册RAG\文档切片\meta_data.json`)中查找匹配度最高的切片，并返回匹配到的json
   3. 意图识别会将用户意图分为三类：
      1. 不相关：与本操作手册智能体无关的问题或敏感、非法的问题，大模型直接拒答
      2. 精确的：用户的问题中包含了上述必要元素，可以精确定位到某一个功能操作手册文档的切片。这类情况大模型直接根据找回的切片回答用户问题。
      3. 模糊的：用户问题中没有完全包含上述必要元素，会匹配到多个功能的操作手册切片。这类情况大模型需要根据返回的文档切片主动深入询问用户，获取缺少的必要元素。比如用户输入：`角色权限有哪些？`，匹配到多个功能的角色权限切片，大模型需要询问用户是哪个功能的角色权限，然后根据用户的回答再次进行意图识别
4. 意图识别按用户问题或子问题分别输出结果：
```json
{
  "input": "对应用户原始输入",
  "simple_input": "简化后的用户问题",
  "module": "功能模块名称或系统名称",
  "role": "用户角色",
  "description": "功能点描述",
  "chunk_id_list": "匹配到的切片id list",
  "intent_type": "意图类型：不相关、精确、模糊",
  "intent_reason": "意图判断依据"
}
```
5. 将意图识别也保存到对话数据库中，方便后续分析
6. 直到用户的问题全部意图识别为精确后才继续下一步：向量检索

### 向量检索

1. 如果用户输入经过意图识别后是包含多个子问题的，那么要依次检索多个子问题
2. 将问题处理为向量，使用稠密检索的方式，返回 top_k=2
3. 最后将所有问题的检索结果合并，并将对话历史一并返回给LLM
4. 同时要将向量检索的结果保存到对话数据库中，方便后续分析
